# Формат профиля Makora

Выбери файловое имя `<provider>-<model>.v<N>.SKILL.md` без слешей и сохраняй точный ID в метаданных. Пример формы, который нужно адаптировать:

```markdown
---
name: "Профиль: Model"
id: "provider/model"
version: "1.0.0"
aliases: ["provider-model"]
role: "executor"
---

# Инструкции к тикету

Опиши проверенные указания для выбранной модели и окружения.
```

`role` описывает назначение профиля. Для оркестратора можно использовать `orchestrator`, для исполнителя — `executor`. Псевдонимы задаются одной строкой. Используй только однозначные псевдонимы и точный ID выбранной модели.

Компилятор добавляет тело профиля в промпт целиком. Храни источники, допущения и замеры отдельно в `dashboard/profiles/research/<provider>-<model>.md` и указывай, какой версии они соответствуют. Если действующая версия заменяется, вынеси прошлую из верхнего уровня каталога профилей или сними конфликтующие ID и псевдонимы. Компилятор по совпадению берёт первый файл в порядке имён.

Выполняй команды из корня Makora. Сначала запусти через путь к файлу, после регистрации — через ID:

```powershell
node dashboard/control.cjs compile "dashboard/profiles/provider-model.v1.SKILL.md" ticket.json
node dashboard/control.cjs compile "provider/model" ticket.json
```

Контрольный тикет передаёт `goal`, `context`, `contract`, `writeScope`, `criteria`, `report`. Существенные требования должны находиться в этих полях. Дополнительные поля остаются в JSON-результате `ticket`. В рабочий текст `prompt` компилятор включает шесть обязательных полей.

В заметке об исследовании укажи ID и окружение, дату проверки, ссылки на первоисточники, гипотезы сообщества и результаты по сопоставимым тикетам. Зафиксируй `черновик`, `проверена компиляция` или `проверено на модели` с подтверждающими данными.
