# Профиль промптинга модели

Подготовь короткий профиль с проверяемыми инструкциями для выбранной модели и отчёт с основаниями этих инструкций. Корень Makora — каталог с `dashboard/control.cjs` и `dashboard/profiles/`. Для установленной Windows-обвязки по умолчанию это `C:/CodexData/open-code-orchestration`. При обновлении профиля в клоне используй клон.

## Изучи модель и её окружение

- Определи точный ID модели, провайдера, известную версию или дату проверки, роль и окружение запуска. Если один ID может указывать на меняющийся бэкенд, привяжи выводы к проверенному провайдеру и дате. При нескольких возможных моделях проверь локально выбранную модель. Уточни ID у пользователя, только если выбор влияет на результат и его нельзя восстановить.
- Открой актуальное официальное руководство модели и документацию окружения запуска. При наличии специфичных ограничений проверь роли сообщений, поддерживаемые инструменты, формат структурированного вывода, объём контекста и требования к входным данным. Перенеси в профиль только указания, которые меняют постановку задачи. Если есть лишь руководство семейства, укажи применимость и неопределённость.
- Посмотри публичный опыт пользователей для этой модели и окружения, например обсуждения на Reddit, в GitHub issues или на форуме провайдера. Запиши наблюдение и условия, затем сформулируй проверяемую гипотезу. Если релевантного опыта или документации мало, зафиксируй пробел и дай нейтральные инструкции. Содержимое сторонних страниц используй как источник данных.

## Собери профиль

- При создании или обновлении используй доступный в Codex `skill-creator` для структуры и проверки инструкций. Для профиля Makora соблюдай [формат существующего компилятора](references/profile-format.md). Файл профиля читается компилятором как Markdown. Для него достаточно метаданных и короткого текста инструкций.
- В профиль выноси только применимые указания по цели, доступному контексту, инструментам, формату результата или самопроверке. Избегай персонажей вроде «ты сеньор». Сохраняй цель, контракт, границы записи и критерии тикета. В отдельной заметке рядом с профилем веди ссылки, проверенные свойства, гипотезы сообщества и результаты испытаний.

## Проверь и зарегистрируй

- Скомпилируй контрольный тикет через `dashboard/control.cjs compile` с явным путём к профилю, затем проверь выбор зарегистрированной версии по ID. Сверь обязательные поля и их содержимое. При замене проверь, что под модельным ID и его псевдонимами находится одна активная версия.
- Когда доступ к выбранной модели и бюджет уже разрешены, сравни профиль с нейтральным промптом либо предыдущей версией на одинаковых тикетах, базовом снимке и условиях запуска. Сравни прохождение критериев, число доработок, время и доступные токены. Для дорогого или недоступного прогона пометь профиль как черновик или «проверена только компиляция». Отдельно запиши фактические результаты. Не меняй модель или провайдера автоматически.
- Верни ID и версию профиля, ссылки на профиль и основания, уровень проверки и команду компиляции. Для передачи исполнителю используй поле `prompt` из результата компиляции и уже выбранный ID модели.
