# Проекты и задачи

[[00 — Makora]] · [[07 — Дашборд CLI и данные]] · [[08 — Идеи и дизайн]] · [[09 — Модели и тикеты]]

## От первого запроса до приёмки

1. **Регистрация проекта.** Makora приводит путь к каноническому виду и связывает проект с каталогом. Повторная регистрация того же пути использует прежнюю карточку. Название можно обновить.
2. **Постановка.** Чат уточняет ожидаемый результат, критерии, режим работы и границы файлов. Исходные пользовательские изменения входят в контекст работы. Улучшения вне запроса можно записать в [[08 — Идеи и дизайн]].
3. **Архитектура и разбиение.** Определяются модули, интерфейсы и проверки. Сильные зависимости выдерживаются последовательностью, независимые задачи получают отдельные области записи.
4. **Исполнение.** Чат формирует тикеты под точную модель. Для обычного потока используются независимые батчи. Для вложенного дерева утверждённые листья выдаёт планировщик.
5. **Проверка и сборка.** Проверяются сессии, diff, границы записи и интеграционные тесты. Прогон привязывается к задаче через `runId` и при необходимости `sessionId`.
6. **Приёмка.** Чат фиксирует доказательство по конкретной версии задачи. Результат сборки сохраняется в отдельной папке. Перенос в исходный проект и финальные проверки выполняются по согласованному процессу.

## Фазы карточки

| Фаза | Смысл |
|---|---|
| `brief` | Постановка и критерии. |
| `architecture` | Границы модулей и контракты. |
| `scaffold` | Каркас и минимальный сквозной сценарий. |
| `implementation` | Рабочие задачи и их исполнители. |
| `assembly` | Сборка проверенных изменений. |
| `acceptance` | Проверка критериев и доказательств. |
| `complete` | Итог этапов зафиксирован. |

Фаза проекта, статус тикета, статус процесса и решение по приёмке хранятся раздельно. Само завершение сессии не переводит проект в `complete`. Фазы обновляются действием `project.phase`; переходы проверяются хранилищем.

## Что хранится в задаче

`task.put` записывает задачу в рамках проекта. Например, карточка может содержать этап, статус, критерии, зависимости и доказательство, а привязка прогона показывает, в какой копии задача выполнялась. `task.accept` фиксирует отдельное решение с `projectId`, `id` и `evidence`.

Доказательство может включать путь к diff, манифесту или журналу тестов и наблюдаемый итог проверки. При чтении панели запись приёмки сравнивается с отпечатком текущей версии задачи. Если значимые поля изменились, старое решение остаётся историческим и текущая версия снова требует приёмки.
