## Локальный запуск

Для текущего проекта нужны Windows, Node.js 22.13 или новее с `node:sqlite` и Git. Для живых исполнителей нужен установленный и авторизованный OpenCode Desktop. Рекурсивный адаптер ожидает CLI 2.3.0. Обычная панель и просмотр записанных результатов работают без вызовов моделей.

Команда запуска выполняется из корня локального клона.

```powershell
npm ci --ignore-scripts
$env:DASHBOARD_DATA_DIR = Join-Path $env:LOCALAPPDATA 'Codex/OpenCode Dashboard'
node ./dashboard/server.cjs
```

Рабочий адрес по умолчанию — [http://127.0.0.1:18741/](http://127.0.0.1:18741/). При занятом порте можно выбрать другой через `DASHBOARD_PORT`. Укажи этот же порт в `control.cjs --port` или в окружении. Для отдельного испытания используй отдельные порт и `DASHBOARD_DATA_DIR`, чтобы рабочая база и тестовая база не смешивались.

Рекурсивное исполнение включается отдельным JSON по абсолютному пути в `MAKORA_RECURSIVE_CONFIG`. Минимальная конфигурация приведена ниже.

```json
{
  "enabled": true,
  "root": "D:/MakoraRuns"
}
```

Каталог `root` создаётся заранее и находится вне исходного проекта. Для Python-проверок рекурсивного режима задаётся абсолютный `execution.pythonPath`. Проверки выполняют `node` или `python` с массивом аргументов и рабочей папкой копии. Одобренные проверки выполняют код под правами пользователя панели, поэтому имеет значение доверие к командам и их исходникам.

## Лимиты рекурсивного режима

| Ограничение по умолчанию | Значение |
|---|---:|
| Параллельные исполнители в батче | 2 |
| Узлы | 24 |
| Исполнительские попытки на прогон | 24 |
| Исполнительские попытки на лист | 2 |
| Время исполнительской попытки | 30 минут |
| Активное время прогона | 120 минут |
| Проверяемые работы и интеграции суммарно | 36 |
| Интеграции ветвей | 24 |
| Запросы ревью | 8 |
| Запросы перепланирования | 4 |

Попытки и счётчики сохраняются при перепланировании. Время считается по объединению активных интервалов. Ожидание ответа из чата в активное время не входит. Токены и стоимость учитываются по доступной полной телеметрии. Нулевые значения `tokens` и `costMicros` оставляют наблюдение без порога. Порог применяется при допуске нового модельного вызова. Возможность остановить уже начатый вызов по стоимости зависит от провайдера. [Константы лимитов](../../dashboard/recursive/plan.cjs)

## Пауза, отмена, перезапуск

- **Пауза** запрещает выдачу новых операций. Активная работа может завершиться. Уже подготовленный пакет ревью можно обработать из чата.
- **Продолжение** возвращает приостановленный запуск к планированию. При неопределённой попытке сначала нужно подтвердить судьбу прежней сессии. См. известное исключение при изменении исходника в [[11 — Пилот и границы проверки]].
- **Отмена** устанавливает `cancelling`, закрывает ожидающие локальные запросы ревью и останавливает принадлежащие запуску сессии. По завершении проверки появляется `cancelled`.
- **Перезапуск** сверяет SQLite с исходным снимком, журналами и сохранёнными результатами. Подтверждённый итог старой попытки можно импортировать без запуска нового исполнителя. При отсутствии доказательств Makora сохраняет `unknown`.
- **Обычное демо** управляется отдельно. У работающего дашборда есть список принадлежащих ему процессов. После перезапуска прежняя готовность демо считается неподтверждённой.

## Диагностика по симптомам

| Видимый симптом | Где искать причину |
|---|---|
| Страница не открывается | Проверить процесс панели, порт и `GET /api/health`. Отказ соединения говорит о недоступном слушателе на этом адресе. |
| Нет плана в панели | Проверить выбранный проект, канонический путь, порт и используемую SQLite. |
| Старт недоступен | Проверить конфигурацию рекурсивного режима, номер и отпечаток утверждаемой ревизии, незавершённый запуск и доступ к папке снимков. |
| «Ожидается решение из чата Codex» | Найти `plan.review.pending` по правильным `projectId` и `runId`, прочитать доказательства и сверить хеши перед решением. |
| Батч завершился до результата | Сверить `batch.out`, `batch.err`, `managed-run.json`, `summary.json`, журналы работников и доступность Desktop. |
| Провайдер ответил `429` | Уточнить причину и `retryAfterMs` в JSONL. Сохранить модель и результаты попытки. В [[11 — Пилот и границы проверки]] приведён пример. |
| Конфликт правок | Сравнить `beforeHash`, текущий хеш, список зависимостей и владельцев путей. См. [[06 — Рабочие копии и сборка]]. |
| Отмена остаётся в процессе | Проверить принадлежность и состояние реальных сессий и локальных проверок. Пока терминальное состояние не подтверждено, повторная выдача может создать дубликат. |

Для воспроизведения проблемы полезны `projectId`, ревизия плана, `runId`, ID попытки, worker name, ID обеих сессий, время события и пути к доказательствам. Сырые журналы могут содержать тикеты и локальные пути, поэтому для обмена достаточно нужного фрагмента.
