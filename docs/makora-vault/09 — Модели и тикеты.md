## Кто выбирает модель

Выбранная модель — часть утверждённого задания. В самостоятельном батче при отсутствии явного значения используется `opencode/big-pickle`. В рекурсивном листе модель и профиль указываются явно, с одинаковым точным идентификатором формата `opencode/…`. Ошибка провайдера фиксируется в журнале; автоматического переключения на другой вариант в этом потоке нет.

Локальный реестр содержит профиль `opencode/big-pickle` для исполнителя и профиль `gpt-6.2-sol` для роли оркестратора. Наличие Markdown-профиля означает наличие формата промпта. Оно само по себе не запускает модель и не подтверждает доступ к провайдеру. В текущем процессе ревью делает активный чат.

## Контракт одного тикета

| Поле | Что дать исполнителю |
|---|---|
| `goal` | Наблюдаемая цель одной законченной работы. |
| `context` | Применимые входы, решения и ограничения проекта. |
| `contract` | Поведение интерфейса, входы и выходы, совместимость, обработка ошибок. |
| `writeScope` | Конкретные файлы или каталоги, которыми владеет исполнитель. |
| `criteria` | Результаты, которые можно наблюдать и проверить. |
| `report` | Что вернуть в отчёте, включая изменения, результаты и ограничения. |
| `checks` | Дополнительное поле для команд. Рекурсивный режим задаёт команды отдельным структурированным списком в узле плана. |

Тикет должен быть достаточно полным, чтобы агент мог действовать в своей копии. Общие файлы следует закреплять за одним исполнителем. Если задача зависит от свежего результата другой ветки, зависимость оформляется в плане. Передача договорённости на словах не заменяет сохранённый входной артефакт.

## Компиляция профиля

```powershell
node ./dashboard/control.cjs compile big-pickle "<ticket.json>"
```

Команда локально загружает версионированный Markdown-профиль. Она оставляет поля исходного тикета в результате и добавляет `profile`, `version` и `prompt`. В исполнительский батч передаётся `prompt`. Компиляция не обращается к провайдеру. Рекурсивный адаптер сверяет точное совпадение профиля с утверждённой моделью.

В профилях разделены официальные рекомендации, эмпирические наблюдения и критерии сравнения. Если для выбранной модели нужен новый профиль, ведётся отдельная проверка гипотез на сопоставимых заданиях. Результаты одной модели на одном пилоте не дают замера для другой модели.
