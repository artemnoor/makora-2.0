# Дашборд, CLI и данные

## Что показывает панель

| Вкладка | Содержимое |
|---|---|
| Обзор | Выбранный проект, текущая фаза, задачи, блокировки и решения. |
| Git | Рабочие копии, наблюдаемые прогоны, сессии и сведения о сборках. |
| Идеи | Исходный текст, предложенный момент реализации и решения по идеям. |
| Лаборатории | Обычные демо-карточки и раздел рекурсивных планов при их наличии. |
| Аутсорс | ТЗ и контракт OpenAPI, загрузка ZIP, приёмка и перенос результата. См. [[13 — Аутсорс модулей]]. |
| Дизайн | Референсы, подтверждения, синхронизированные фреймы Figma и этапы реализации дизайна. |

Браузер периодически запрашивает состояние сервера. Он показывает, какие команды доступны, а допустимость переходов окончательно проверяет сервер. Видимый статус OpenCode и приёмка задачи — отдельные поля.

## HTTP и локальная команда

Сервер по умолчанию слушает `127.0.0.1:18741`.

| Маршрут | Назначение |
|---|---|
| `GET /` | Панель. |
| `GET /api/health` | Доступность экземпляра. |
| `GET /api/state` | Проекты и их текущее состояние. |
| `GET /api/audit?projectId=…` | Записи аудита выбранного проекта. |
| `POST /api/actions` | Локальные действия с JSON-телом. |
| `/api/outsources/<projectId>/<id>/<resource>` | Скачивание ТЗ и OpenAPI, загрузка ZIP. |

```powershell
node ./dashboard/control.cjs state
node ./dashboard/control.cjs state --port 18746
node ./dashboard/control.cjs action "<action.json>"
```

Поддерживаются JSON-файл UTF‑8 и передача JSON в команду. Для действий внимательно проверяй поля `ok`, `code` и `error`. Ошибка бизнес-правила может вернуться с HTTP 200 и `ok: false`. Общий предел тела действия — 64 КиБ.

Браузерные подтверждения защищены проверками loopback `Host`, соответствующего `Origin` и, когда он есть, `Sec-Fetch-Site`. К этой категории относятся решения по идеям и демо, старт и управление планом, подтверждение референсов и макета. Команды чтения и фиксации рекурсивного ревью, публикации плана и синхронизации Figma доступны локальному CLI. Эти признаки разделяют обычные пути действий и защищают от постороннего браузерного источника. Локальные процессы с доступом к серверу находятся в доверенной среде.

| Объект | Действия |
|---|---|

| Задачи | `task.put`, `task.accept` |
| Идеи | `idea.add`, `idea.decide` |
| Демо | `lab.propose`, `lab.configure`, `lab.decide`, `lab.start`, `lab.stop` |

## Что хранится где

| Источник | Роль |
|---|---|
| `DASHBOARD_DATA_DIR/dashboard.sqlite` | Основные таблицы `projects`, `tasks`, `ideas`, `labs`, `designs`, `outsources`, `runs`, `task_acceptances`, `decisions`, `audit`. Текущая версия схемы — 3. |
| Рекурсивные таблицы SQLite | `plans`, `work_nodes`, `node_dependencies`, `plan_runs`, `attempts`, `artifacts`, `reviews`. |
| Каталог рабочих прогонов | Снимки, рабочие копии, манифесты, diff, журналы, файлы владения сессиями, результаты проверок и сборки. |
| OpenCode Desktop | Исходные сессии моделей и их события. ID связывает сессию с локальными доказательствами Makora. |
| Текущий чат | Постановка, анализ и смысловая интерпретация критериев. Решения, необходимые для следующего шага Makora, публикуются в её SQLite через API. |

SQLite разделяет план, запуск и попытку. У одного плана может быть несколько ревизий. Один запуск включает попытки с разными результатами, а изменения состояния сохраняются транзакционно. Наблюдатель дополнительно читает манифесты и журналы прогонов, сопоставляя их с каноническим путём проекта. Его наблюдение помогает искать доказательства; статус «завершён» в журнале не помечает задачу принятой.
