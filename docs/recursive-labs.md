# Рекурсивные лаборатории Makora

Режим работает в локальном дашборде на вкладке «Лаборатории». Текущий чат Codex составляет план и проверяет результаты. В `MAKORA_RECURSIVE_CONFIG` задаётся абсолютный путь к отдельному JSON. Этот пример включает планировщик.

```json
{
  "enabled": true,
  "root": "C:/MakoraRuns"
}
```

`root` должен существовать вне проекта. Рабочие копии и вся история остаются в нём. SQLite добавляет таблицы версии 2 при запуске панели. Для Python-проверок нужен абсолютный `execution.pythonPath`. При включении планировщика обработка ранее утверждённых незавершённых запусков возобновляется из базы.

## План и полномочия

1. Зарегистрируйте проект по каноническому пути. Опубликуйте JSON действием `plan.put` через `node ./dashboard/control.cjs action <plan.json>`. Укажите `projectId`, `id`, `title`, `requirements`, `nodes` и `expectedRevision` при замене черновика. Каждый узел содержит `id`, `parentId`, `kind`, `title`, `criteria`, `checks` и при необходимости `dependsOn`. Для листа нужны `goal`, `contract`, `writeScope`, `model` и профиль точной модели в `profile`.
2. Действие `plan.draft` строит дерево из списка `work`. Укажите корневые `integration.criteria` и `integration.checks`. Листы можно сгруппировать по полю `group`, задав критерии и проверки для группы в объекте `groups`. Содержимое задач, модель и команды задаёт автор плана.
3. Панель показывает дерево, модели, команды и бюджет. Кнопка утверждает конкретную ревизию и хеш. Снимок включает рабочие файлы, включая локальные staged, unstaged и untracked изменения по правилам Git. `baseline.json` содержит исходный HEAD, статусы файлов, хеши содержимого и список исключений. Для удалённого или исключённого файла записывается `null`.
4. `plan.revise` принимает `projectId`, `runId`, `revision` и полный обновлённый `plan`. Выполненные артефакты с совместимыми входами сохраняются. Изменения требований, команд, модели, прав или лимитов публикуются отдельным черновиком и требуют нового утверждения. Бюджет сохраняется во всех автоматических ревизиях.

Проверки передаются как `{ "executable": "node", "args": ["--test"] }` или с `python`. Команды утверждает пользователь. Они запускаются в отдельной копии с сокращённым окружением под учётной записью дашборда. `writeScope` проверяется после исполнения в E Verified Batch. Для недоверенного исполняемого кода нужна изоляция средствами ОС.

## Исполнение и приёмка

Листья с одинаковыми входами и непересекающимися областями записи объединяются в один E Verified Batch. Управляемый режим использует установленный OpenCode Desktop CLI **2.3.0**, проверяет локальный OpenAPI и записывает ID сессии до отправки задания. При отмене сверяет дерево принадлежащих запуску сессий, убирает их очереди и вызывает `session.interrupt` с `resume=false`.

Манифест артефакта фиксирует `inputManifestHash`, `dependencyArtifacts`, `verificationHash` и `beforeHash`/`afterHash` для каждого пути. Композиция проверяет предыдущие хеши, конфликты путей и байты итоговой сборки. Внутри группы лист может использовать предварительный результат соседа. Отклонение источника инвалидирует его потребителей. Передача между группами требует принятого результата. Ветка проходит интеграционные проверки, а ревью может принять её и проверенных потомков одним решением по точным хешам и совокупным критериям. Перед приёмкой корня Makora сверяет исходный проект со снимком. Путь принятой сборки и доказательства появляются в панели.

Пауза останавливает выдачу заданий. Продолжение возобновляет планирование. При отмене показывается промежуточный статус, пока завершение принадлежащих запуску сессий не подтверждено. Неопределённые попытки сохраняют ID, журналы и артефакты. Повторная отправка в исходную сессию исключена. Результат с сохранёнными доказательствами восстанавливается по журналу попытки.

## Ревью из текущего чата

В текущем чате Codex разбивает задачу на работы, определяет зависимости и публикует план через локальный CLI. Пользователь утверждает ревизию в панели. Дашборд создаёт пакеты ревью по мере готовности сборок. Независимые задачи продолжаются, а зависимые ждут решения из чата.

`plan.review.pending` принимает `projectId` и `runId`. Ответ содержит ID запроса, ревизию, хеши сборки и проверок, критерии, diff, логи и путь к сборке. `plan.review.decide` принимает те же `projectId` и `runId`, а также `requestId`, `assemblyHash`, `verificationHash`, `decision` и массив строк `findings`. Для запроса перепланирования положительное решение содержит `proposal` с полной новой версией плана. Просроченные ревизии и несовпадающие хеши отклоняются. Обе команды выполняются через `control.cjs action`.

Запросы сохраняются в SQLite и доступны после перезапуска. Пока чат закрыт, Makora продолжает готовую независимую работу. Приёмка и изменение плана ждут решения из чата. Ожидание ответа из чата не расходует время исполнителя и не создаёт отдельных модельных вызовов.

## Бюджет и пилот

Начальные лимиты составляют 2 параллельных исполнителя, 24 узла, 24 исполнительские попытки, 2 попытки на лист, 30 минут на исполнительскую попытку и 120 минут активного времени. Отдельно учитываются интеграционные проверки, запросы ревью и перепланирования. Макора суммирует активные интервалы с учётом их пересечения.

Токены и стоимость сохраняются, когда исполнитель или ревьюер предоставил полную телеметрию. `limits.tokens` и `limits.costMicros` задают пороги допуска новых вызовов. Если указанный порог невозможно сверить после завершённого вызова, планировщик блокирует новые вызовы. Жёсткий лимит внутри уже запущенной сессии зависит от провайдера. Нулевое значение оставляет наблюдение включённым без порога.

Локальные тесты выполняются с тестовыми адаптерами.

```powershell
npm ci --ignore-scripts
npm test
```

Для отдельного сравнительного пилота фиксируются входной манифест, задачи, критерии, модель, бюджет и результаты проверок. Сначала сравниваются рекурсивный режим и E Verified Batch с одной и той же моделью. Для DeepSeek нужен отдельный утверждённый прогон с точным ID и профилем. Сопоставляются приёмка, активное время, число попыток и ревью, конфликты и подтверждённые затраты. Карта исследований и ограничений собрана в [каталоге источников](recursive-labs-sources.md).
